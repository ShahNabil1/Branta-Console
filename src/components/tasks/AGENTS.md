- Company Tasks publish states: publish_state draft/scheduled/live + scheduled_at; a schedule is live once scheduled_at <= now() (RLS + taskBucket in company-task-rules.ts, no cron), drafts/pending schedules visible only to task managers, only not-yet-live tasks can be hard-deleted — why: exact go-live without a job and no history loss.
- Company Task board column follows assignee progress via DB trigger sync_company_task_status (any started → Doing, all submitted/approved → In Review, all not started → To Do, Done never moved; mirrored by boardStatusFromAssignees); task server fns validate through zp() for readable errors — why: assignees cannot update company_tasks under RLS and must not see raw validation JSON.
- Company Tasks (/app/tasks, /app/org/<slug>/tasks) live in company_tasks + child tables via company-tasks.functions.ts; permissions only via can_manage_company_tasks (Group Admin, company C.E.O/C.O.O/HR) and can_work_company_task (manager or assignee), rules mirrored in company-task-rules.ts; the New Task drawer reuses ExpenseDrawerContent/DrawerStepper — why: one per-company pipeline where viewers read, assignees work and managers own everything.
- Company Task submission files (images/PDF/ZIP) upload straight to Cloudflare R2 under tasks/<task>/<user>/ via requestTaskFileUpload (DB trigger checks the prefix), are signed for reading in getCompanyTask and viewed with the shared ReceiptThumb/ReceiptPreview/ExpenseReceiptsGallery — why: never Supabase Storage, one proof viewer everywhere.
- Task asset/reference files upload to R2 under task-assets/<company>/<uploader>/ via requestTaskAssetUpload (manager-only), stored in company_task_assets.file (url = r2:<key>) with optional subtask_id; previews reuse receipt-media — why: same R2/gallery flow as submissions, no Supabase Storage.
