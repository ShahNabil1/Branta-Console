- Tracker Shift schedules are admin-edited only via tracker-schedule.functions.ts into Tracker app_metadata.shift_schedule; the extension computes Late/Early/Overtime — why: employees cannot edit app_metadata.
- Sister-company money lives only in append-only company_wallet_ledger via SECURITY DEFINER RPCs (credit installment, debit expense, move, reverse, loan decide); fund splits are versioned company_fund_configs (custom-named funds, fixed ৳ first then % of the rest = 100%, split math mirrored in company-fund-split.ts; no separate deduction rules) — why: Branta's fund_ledger stays untouched and history never changes.
- Sister-company creation gates live in the DB (company_gate_trigger on leads/customers/invoices/expenses: all four code prefixes, plus active Fund Allocation for invoice/expense); company-setup.functions.ts only reports what is missing — why: no UI path or fallback can bypass setup.
- Company URLs: Branta Tech (holding) uses /app/..., each sister company /app/org/<slug>/... (org-path.ts); shared pages live in src/components/pages and are mounted by both route files; OrgBridge moves plain company pages into the selected sister workspace and remembers the last page for sign-in — why: the URL decides the company, so tabs/links never mix companies.
