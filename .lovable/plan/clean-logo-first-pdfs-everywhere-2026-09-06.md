# Clean, logo-first PDFs everywhere

Use your own two logos (colour + white) across every PDF, strip the extra marketing text, and add one small line showing who generated the file and from which device.

## What changes on the page

**Header (all PDFs: invoice, expense voucher, money receipt, salary slip, finance/salary reports)**
- Your logo only — the white logo when it sits on the orange band, the colour logo on white background.
- Removed: the typed company name next to the logo, the tagline, "Creative Technology Company", "Grow Smarter with AI", and the address block in the header.
- Kept: a thin orange rule, and on the right only the document title (INVOICE / EXPENSE VOUCHER / MONEY RECEIPT / SALARY SLIP / report name), its number, and date.

**Body**
- Untouched. Invoice keeps parties, line items, project cost, installments, totals, amount in words, signature block. Expense voucher keeps txn ID, method, department, requested by, purpose. Salary slip keeps pay lines, barcode, signature areas, accounts manager. Reports keep filters, summary cards and tables.
- One redundancy removed: the repeated company name inside signature/stamp captions.

**Footer (one compact line, same on every PDF)**
- Contact strip: phone · email · website (no marketing sentence).
- Below it, small grey: `Generated by <user name> · <device / browser> · <date time GMT+6> · Page x of y`.

## Logos

- Upload both `Asset_1.png` (colour) and `Asset_3.png` (white) as project assets and reference them from the PDF code, so no admin setup is needed. A custom logo URL set in Invoice Settings still overrides the colour logo when present.
- Print mode (pre-printed letterhead) stays blank in the margins as today — no logo, no footer strip; only the generation line is omitted too.

## Technical notes

- Files touched: `src/lib/invoice-pdf.server.ts` (invoice, voucher/receipt, salary slip headers/footers), `src/lib/finance-report-pdf.server.ts` (both finance and generic/salary report builders), plus the route/server functions that build PDF inputs so they can pass the generator identity.
- Logos are embedded as base64 modules under `src/lib/brand/` (Worker runtime has no reliable outbound fetch guarantee at render time); the existing `tryFetchImage` path stays for user-supplied `logo_url`.
- Generator identity: PDF input gains `generatedBy?: { name: string; device: string }`. Name comes from the authenticated profile; device is parsed from the request `user-agent` (e.g. "Chrome on macOS"). Public signed-link downloads that have no session render the line as `Shared link · <device>`.
- No change to calculations, currency, permissions, signing, upload or export logic.
